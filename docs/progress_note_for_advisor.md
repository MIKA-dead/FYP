# Motion Studio 代理系统 — 近期进度简报

**项目**：多模态动画生成代理（Intent 路由 → 规划 → MotionsFix/几何编辑 → 质量门 → Session UI）  
**用途**：发给导师的阶段小结（sit / wave 修订链路）

---

## 1. 本阶段做了什么

### 1.1 Session 交互与编排
- 搭建 Session UI（聊天 + 右侧预览 + 时间轴），`chat_server` 对接 orchestrator。
- 统一走 `run_module`：planner 出 Intent / MotionEditPlan，coder 调后端，tester 做 quality gate。
- 支持 generate / revise；demo 缓存可快速演示，也可关闭后跑全量管线。

### 1.2 修订（Refine）闭环
- 闭集 Refine 算子：删段 / 减速 / 加速等，时间轴点选与自然语言共用同一 JSON 结构。
- 理解路径：优先 LLM（OpenCode Go / DeepSeek）编译用户说法；失败则启发式兜底。
- 时间轴：sit / wave / walk / turn 按动作自动分段；UI 可拉伸，避免挡住预览。

### 1.3 编辑“记忆”与加强执行
- 增加可更新的编辑配方库（`edit_recipes.json`）：按动作 + 意图 + 时间轴相位检索，成功/失败回写权重。
- sit 的几何后处理（坐下前裁剪、下降减速等）已基本可用。
- wave 侧增加几何后处理：压侧向跳动、拉前向位移、压非挥手侧手臂（不依赖本机 MLD）。

### 1.4 与 OpenCode / LLM 的衔接
- Refine 使用 OpenCode `auth.json` 凭证调用 zen/go API；服务启动时打印 LLM 是否开启。

---

## 2. 当前效果（答辩/演示相关）

| 能力 | 状态 |
|------|------|
| 理解用户修订说法并对齐时间轴 | 较好（LLM + 配方匹配可见） |
| sit：删前段 / 下降变慢等 | 可用 |
| wave：前走 + 仅右臂挥 | **仍不理想** |
| 任意提示词的稳定、明显改动 | **未达标** |

---

## 3. 现在遇到的主要问题

1. **“听懂了但改不动/改得弱”**  
   MotionsFix 训练分布偏短相对编辑语（如 `wave to the side`），长提示会被压短；原生源（如 001318）本身缺少明显前走，扩散修订后仍易出现侧跳、双臂齐挥。质量门一度过松，出现“分数高但观感差”。

2. **本机 MLD（已修复可跑）**  
   此前 `mld` 环境曾因 spaCy DLL / Windows 策略偶发拦截导致 `coder_failed`。现已复测 `mld_generate` 可正常产出 joints；编排改为 **优先 MLD 前走 → bridge → 运动学挥手 → 几何后处理**，MLD 失败时再回退上一版动作，避免再次整段缺失。

3. **通用性不足（相对“任意提示词都能有效改”的目标）**  
   当前仍偏：理解 → 闭集算子/配方 → 几何或 MotionsFix。缺少稳定的「从数据集检索相似片段 / 可训练改法」闭环；配方与后处理对 sit/wave 较强，对开放域说法的迁移和强度仍不够。

4. **LLM 偶发不可用**  
   OpenCode 上游偶发 503，会退回启发式；理解质量不稳定。

---

## 4. 下一步计划（建议）

1. **稳定 wave「前走 + 右臂挥」**：在不依赖本机 MLD 的前提下，用可用走路源（缓存 / 其它环境预生成）+ 单臂约束 + 更严的质量指标。  
2. **把修订做成更通用的检索–应用流程**：提示 → 对齐当前时间轴 → 检索/更新改法（配方或片段）→ 执行 → 用质量结果回写（可训练更新）。  
3. **评估与消融**：sit/wave 固定用例上记录完成率、时延、是否真改到对应相位，便于写报告。

---

## 5. 一句话总结

Agent **已经能较好地理解修订意图并给出可检查的计划与时间轴**，sit 修订可用；**wave 与开放域提示的实际修改效果仍是瓶颈**，受 MotionsFix 分布、本机 MLD 不可用、以及改法记忆/检索尚浅三方面限制。近期正把路径改为「可运行的几何+配方」并准备加强数据驱动修订。
